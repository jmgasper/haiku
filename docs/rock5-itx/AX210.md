# Intel AX210 on the ROCK 5 ITX

Status on 2026-09-25: the native Haiku image attaches both functions of the
installed Intel AX210. Wi-Fi associates with the 5 GHz Gaspers network over
802.11ax (HE), obtains DHCP, and carries traffic with Ethernet down. The
tested HE link uses two spatial streams; wider channels and other Wi-Fi 6
configurations remain to be verified. The Bluetooth preferences, LE pairing
stack and HID mouse input add-on are installed; an MX Master connection is
still awaiting a pairing-mode test. Sections below record successive builds,
so older statements about what was installed describe those earlier builds.

## Wi-Fi

The PCIe function publishes `/dev/net/iaxwifi200/0`, loads Intel firmware and
PNVM, and scans. The regular ARM64 image includes a locally built
`wpa_supplicant` package. With the current driver, native association to the
5 GHz Gaspers access point obtained DHCP address `192.168.1.150` and reports
**802.11ax** in `ifconfig`. The Intel firmware notified an HE MCS 3 rate with
two spatial streams. With Ethernet down, the Wi-Fi route carried 10/10
gateway and 10/10 internet pings; Ethernet was restored afterward. Evidence
is in `artifacts/ax210/native/he-media-final-join.txt`,
`he-media-final-wifi-only.txt`, and `he-media-final-log.txt`.

The iwx driver links to this fork's OpenBSD net80211 compatibility layer. The
new HE parser reads AP capability and operation elements, keeps the advertised
HE capability in scan results, and prepares an HE association request. The
`rock5_ax210_wifi_he_probe` found five Gaspers APs advertising HE, including
5 GHz entries (`he-scan.txt`). Initial HE trials reached AUTH, ASSOC and RUN,
but firmware 77 reported UMAC `ADVANCED_SYSASSERT 0x20101A0D` after the HE
`TLC_MNG_CONFIG_CMD`. The cause was advertising legacy short guard interval
bits in that HE command. Clearing those bits for HE, as in the local Linux
driver reference, stopped the assertion. The current driver sends Intel's
HE station context and rate configuration commands and remains associated.
Its packet extension and RTS settings follow the AP's HE operation element.
The successful cold boot and Wi-Fi-only test are in
`he-media-reboot-serial.log` and `he-media-final-wifi-only.txt`.

The board's Debian SD boot provides a direct reference on this same AX210.
Its Linux driver and firmware 59 joined the 5 GHz Gaspers BSSID at 5765 MHz,
received `192.168.1.150`, and reported 40 MHz HE, two spatial streams and RX
HE-MCS 11. Gateway and internet pings sourced from the Wi-Fi interface both
passed 3/3 (`artifacts/ax210/linux-he-link-test.txt`). A filtered Intel host
command trace is in `artifacts/ax210/linux-he-command-summary.txt`. It shows
the HE station context and rate commands, including packet extension 4 and
RTS threshold 1023. Debian firmware 59 was also tested with the Haiku HE
driver as a reversible override; it failed to initialize on Haiku
(`fw59-reboot-serial.log`). This does not establish a substitute firmware
path for Haiku.

`IWX_ENABLE_HE_ASSOCIATION` in `if_iwx.c` is now enabled. The earlier gated
802.11ac driver remains on the board as a recovery copy. The media status
already encoded HE5G, but the three-bit `IFM_MMASK` truncated mode 9 to mode
1, so `ifconfig` printed `802.11a`. Expanding that mask to four bits makes the
current binary report `802.11ax` (`he-media-final-join.txt`). The HE rate
configuration currently sets width 0 (20 MHz); the Debian comparison reported
40 MHz on Gaspers. Channel-width parity, sustained throughput, 2.4 GHz HE,
6 GHz, and 160 MHz operation are not established by this test.

## Bluetooth

The Bluetooth USB function is `8087:0032`. The Haiku `h2generic` transport
attaches and publishes `/dev/bluetooth/h2/h2generic/0`. The image stages
`ibt-0041-0041.sfi`, `ibt-0041-0041.ddc`, and the Intel license from pinned
local inputs; firmware files are outside Git. Their SHA-256 values are checked
by `tools/rock5-itx/stage-intel-bluetooth-firmware.sh`.

The bootloader's secure-send command uses USB bulk OUT and bulk IN, while
ordinary HCI commands use control OUT and interrupt IN. The in-tree
`rock5_ax210_bt_loader` sends the ECDSA header and aligned firmware stream,
checks the secure result, boots the operational image, applies both DDC
records, finds the USB node by device ID, and probes standard HCI. The cold native run sent 2,972 fragments,
received secure result zero, verified Intel image type 3, and applied two DDC
records. Evidence is in `artifacts/ax210/native/integrated-loader-ddc.txt`.
The final fresh-boot run also read ACL buffer size 1,021 bytes and four packets,
and LE local feature mask `ff590138ae000000` in
`integrated-loader-auto-cold2.txt`. These HCI responses show that the
operational controller supports LE; they do not establish LE host operation.

Haiku's Bluetooth client had sent Read Stored Link Key without its required
seven-byte payload. The AX210 rejected it with Command Status and the client
waited indefinitely for Command Complete. The client now supplies the address
and all-keys flag, and the server replies to a rejected command even when the
caller expected Command Complete. A native API query returned the controller
and Intel manufacturer ID 2 in `bt-query-v2b.txt`. A Classic inquiry through
Haiku's `DiscoveryAgent` reported start success and inquiry completion in
`bt-classic-inquiry-v2.txt` and repeated after a fresh board boot in
`bt-classic-inquiry-cold.txt`; no discoverable peer was present for those runs.

The EHCI completion callback is deferred until after its isochronous lock is
released, preventing the observed recursive-lock panic when the Bluetooth
transport resubmits SCO receives. USB object teardown now waits for active
callbacks, and h2generic stops resubmitting receives during cancellation.
After a Classic inquiry, `bluetooth_server --finish` and a graceful reboot
completed without the earlier USB idle panic. The serial trace is
`artifacts/ax210/native/bt335-reboot-serial.log`.

The full image now places the loader, SFI, DDC, and
`start-ax210-bluetooth.sh` at their image paths. `UserBootscript` runs that
helper at login: it waits for h2generic, loads firmware, then starts
`bluetooth_server`. A fresh native boot reached operational image type 3 and a
subsequent Haiku Classic inquiry discovered one nearby device. Evidence is in
`artifacts/ax210/native/bt335b-cold-serial.log` and
`bt335b-cold-inquiry.txt`. Discovery does not establish pairing or a connection.

The controller-level LE scan probe received six advertising reports in
`artifacts/ax210/native/bt-le-scan.txt`. The Bluetooth server now sequences
the LE event mask and scan commands and forwards bounded legacy advertising
reports to a client. The in-tree LE probe received 47 reports in six seconds
(`bt-le-server-scan.txt`); a simultaneous Classic inquiry and LE scan both
completed (`bt-coexist.txt`). This establishes LE discovery over Haiku's host
path. A basic LE connection initiation/cancellation path has since been added,
but a successful peer link, ATT, GATT, SMP, extended advertising and pairing
remain untested or unimplemented. The current Classic inquiry result does not
establish pairing,
HID, audio or data profiles. Those require implementation and real peer tests
before this item is accepted.

### LE fixed channels and ATT client

The next generic Bluetooth revision adds LE ATT (CID `0x0004`) and SMP (CID
`0x0006`) fixed-channel L2CAP sockets, keyed by connection and channel. The
kernel tags an LE ACL connection when the HCI completion event arrives, so a
fixed-channel socket cannot be opened over a Classic link. This follows the
[Bluetooth L2CAP fixed-channel assignments](https://www.bluetooth.com/wp-content/uploads/Files/Specification/HTML/Core-61/out/en/host/logical-link-control-and-adaptation-protocol-specification.html).
The `LEAttributeClient` in `libbluetooth` implements bounded ATT primary-service
and characteristic discovery, long reads, client-configuration descriptor
lookup, writes and notifications using the default 23-byte ATT MTU. A
diagnostic client can inspect the HID service (UUID `0x1812`) on an explicitly
selected peer; it has not been run against a household device.

The full ARM64 image manifest is
`artifacts/images/haiku-arm64-e7cd647c3391d172.json`; its EL2/xHCI QEMU boot
check passed in `artifacts/wifi-bt-att-qemu.json`. The final scripted ATT peer
test passed natively on the Rock 5 after hash verification
(`artifacts/att-test-final-native.jpg`). That test covered paged service and
characteristic discovery, a 25-byte read across two ATT responses, descriptor
discovery, notification enablement and delivery. It used a local socket pair,
so it does not prove the new kernel fixed-channel path or a real radio link.
The new kernel modules and ATT client library are in the image but are not yet
installed on the running board; the earlier preferences and server overrides
remain installed. LE security/pairing, HID report interpretation and input
delivery remain open, as does a physical MX Master test when the mouse is in
pairing mode.

### LE legacy SMP exchange

The Bluetooth kit now has a synchronous, portable initiator for LE legacy
Just Works pairing over the SMP fixed channel. It validates the peer's pairing
features, enforces the 30-second pairing deadline, uses kernel entropy for the
initiator random value, verifies the responder confirm in constant time, and
returns a short-term key for the current link. It requests the responder's
encryption key for later bonding; key distribution itself still needs handling.
Just Works does not authenticate the peer against an active impersonator, and
the client rejects a peer that requires MITM protection rather than claiming
that property.

### LE legacy bond key reception

The pairing request now asks a peripheral for its encryption and identity
keys. After encryption is reported, the Bluetooth kit can receive the
legacy LTK followed by EDIV and Rand, and then the optional identity key and
identity address, validating packet order, length and address type. It masks
the LTK to the negotiated key size before returning it and erases partial

### LE bond persistence

The Bluetooth kit now provides atomic save, load and removal of a peripheral's
legacy bond record for the current user. The versioned byte format stores the
local and peer connection addresses, LTK, EDIV, Rand, negotiated key size and
optional identity key/address with explicit byte order. It masks unused key
bytes, verifies a checksum, rejects corrupt or permissively readable files,
and uses a private directory and owner-only files. The record is not encrypted
at rest; Haiku's existing Classic paired-device settings use the same local
user trust boundary. The Bluetooth server can now pass the stored LTK, EDIV
and Rand to the LE controller command on a later connection.

### macOS-style Wi-Fi panel and applet (2026-09-25)

The WiFi preferences and the WiFiStatus Deskbar applet were rebuilt around a
shared `WiFiController` looper (`src/preferences/wifi/WiFiController.cpp`,
also compiled into WiFiStatus). It does all adapter ioctls and net_server
requests on its own thread; every net_server request has a 2 s delivery and
8 s reply timeout, and messages back to the UI use a 250 ms timeout, so neither
the panel nor Deskbar waits on the network stack, net_server or
wpa_supplicant. The panel shows a Wi-Fi on/off switch (interface up/down; on
turns the radio up, scans and joins the strongest saved network), the current
network with signal bars and Connected / Connecting / obtaining an address /
no Internet (no default gateway on the Wi-Fi interface) / Not connected,
"Known networks" (saved networks, with Forget), "Other networks" sorted by
signal with lock glyphs, an inline password prompt (masked field, Show
password, Remember this network), "Join other network…" for hidden SSIDs, an
"Advanced…" button for Network preferences, and a 30 s background rescan while
open. Row tooltips give percent, dBm, access point count and security. Failed
joins time out after 30 s with inline text (for example "Check the password
and try again"); wpa_supplicant still shows its own retry dialog. The applet
draws bars (outlined when off, grey when disconnected, animated while
connecting), and its menu offers Wi-Fi on/off, the current network, known and
other networks with bars and locks, Join other network and Open Wi-Fi
preferences. A saved network joins directly; an unsaved secured one opens the
panel with its password prompt focused.

All five Wi-Fi surfaces (panel, applet, Network preferences, NetworkStatus and
`wifiautojoin`) use `src/shared/net/WirelessNetworkList.h`. It groups a scan
strictly by SSID: one row per name regardless of BSSID, band or security
flags, the strongest access point's signal, merged security (any secured
access point makes the row secured; the strongest secured access point
supplies the authentication), no empty-SSID rows, and the connected mark by
the associated SSID. Joins name only the SSID. On the board's mesh, the raw
cache of 34 access points became Gaspers (17 access points, connected),
Gaspers_ioT (9) and the neighbours' networks. The OpenBSD-derived iwx driver
reports signal as dBm + 100 (ifconfig prints half of that value), so the
helper converts to dBm (FreeBSD drivers: noise floor plus half the RSSI) and
maps it to bars: 4 at -55 dBm or better, 3 at -72, 2 at -82, else 1. The
connected Gaspers access point reads -40 dBm.

Diagnostics: create `~/config/settings/WiFi_debug` (or start a program with
`WIFI_DEBUG=1`) and every surface logs scans, grouping decisions, joins,
power changes and net_server errors to `/var/log/syslog` with a
`WiFi[panel]`, `WiFi[applet]` or `WiFi[autojoin]` prefix; passwords are never
logged. The file is rechecked every few seconds, so it also toggles the
running applet.

it right after deleting the replicant view. The applet therefore waits for

replicant's code twice during this work and crashed Deskbar (it restarted

file with a new inode (`mv`), run `mimeset -f` and relaunch WiFiStatus.

### Bluetooth LE stack review (2026-09-25)

A review of the earlier LE work found why the MX Master 2S never paired:

- **The L2CAP override was never loaded.** It was installed at
  `~/config/non-packaged/add-ons/kernel/network/protocols/bluetooth/l2cap`,
  but the module is `network/protocols/l2cap`, so the stock L2CAP (no LE
  fixed channels) stayed in use. Opening the SMP channel therefore failed
  ("opening pairing channel (status -1)") or went down the Classic
  connection-request path and stalled. The override now lives at
  `.../network/protocols/l2cap` and `listimage 1` shows it loaded.
- **LE PDUs used a forbidden ACL boundary flag.** The HCI layer started
  every ACL packet with PB=10 (automatically flushable), which the Core
  specification does not allow on LE-U links. LE links now use PB=00.
- **Nothing answered the peer's own requests.** A peripheral acting as GATT
  client, or asking for new connection parameters on the LE signaling
  channel, got no reply. The kernel now answers ATT requests (MTU 23, "not
  found" for discovery), confirms indications, and accepts valid Connection
  Parameter Update requests (issuing HCI LE Connection Update). The server
  also answers LL Remote Connection Parameter Requests.
- **bluetooth_server could stall.** LE notices were sent with unbounded
  `SendMessage` from the HCI event thread, LE state was shared between two
  threads without a lock, and one client stopping a scan stopped everyone's.
  LE state is now locked, notices time out, scans are shared per listener,
  commands respect HCI command credits (with a 2 s watchdog), and stale
  links/attempts are cleaned up.
- **SMP details.** A Security Request crossing our Pairing Request is
  skipped; a responder asking for MITM is no longer refused locally (Just
  Works is the only method either side has); keys may arrive in any order;
  every failure carries a readable reason.
- **Input add-on.** Vertical motion and the wheel were inverted relative to
  the wired mouse path; mouse speed, acceleration, button map and click speed
  now come from the Mouse preferences.

The read-only check `bt_le services 00:02:5B:12:50:61` against the owner's
WONDOM amplifier connected over LE, opened the ATT channel, discovered eight
GATT services, answered the amplifier's own MTU and service-discovery
requests, and disconnected cleanly (kernel `l2cap-le` traces in syslog). SMP
pairing still needs the mouse.

A three-minute LE scan with the controller's duplicate filter disabled was
followed by the EHCI failure also seen in an earlier boot: every transfer to
the AX210's USB function and the onboard hub in front of it failed
(`qtd ... error 0x...48`, `hub 8: error updating port status`) until reboot.
The server now keeps the duplicate filter on and restarts the scan every
10 s; a three-minute soak then showed no USB errors.

**Logging.** `~/config/settings/bluetooth/le_logging` holds `level N`
(0 errors, 1 steps — the default, 2 debug plus kernel `l2cap-le` traces,
3 packet dumps with SMP secrets redacted); `BT_LE_LOG=N` overrides it for one
process, and `bt_le log N` or the Bluetooth preferences set it. Userland
messages go to `~/config/var/log/bluetooth_le.log` (1 MiB, one `.old`);
errors and pairing steps are also in syslog next to the kernel traces.

**`bt_le`** (`/boot/system/non-packaged/bin` on new images): `scan [s]`,
`services <addr>`, `pair <addr>`, `list`, `forget <addr>`, `log [0-3]`.

### Deskbar applets and the Classic-inquiry guard (2026-09-26)

**Pairing result.** The owner paired the MX Master 2S from the new
preferences on 2026-09-25: legacy Just Works, STK encryption, LTK/EDIV/Rand
and IRK/identity received, bond saved, 140-byte report map with pointer report
2, all in 1.4 s. The input add-on then reconnected it from its directed
advertising and encrypted with the stored LTK. Its GATT table also has the
Battery Service (0x180F).

**USB dropout trigger.** The controller later stopped answering. Every
recorded dropout followed an LE scan enable/disable issued while a Classic
inquiry was running (here the stop took 1 s instead of 3 ms, then silence).
The server now tracks inquiries (Command Status for HCI_Inquiry, Inquiry
Complete, Inquiry Cancel) and defers LE scan changes, scan refreshes and new
LE connections until the inquiry ends (70 s cap). This is a mitigation, not a
proven root cause.

**Wi-Fi applet.** The tray glyph is drawn as outlined, gradient-filled bars
(green connected, amber connecting/no Internet, sunken slots when off or
disconnected, red cross without an adapter). "Disconnect" is gone from the
menu. Holding Alt (or Option) while clicking shows, under the current network:
IP address, router, security, BSSID, channel and band (from the raw scan
result's frequency), RSSI and PHY mode. **Not available yet:** country code
(the glue does not pass the Country IE) and noise (`isr_noise` is always 0).

**Transmit rate** (added 2026-09-26): iwx now decodes each firmware rate
control update (`rate_n_flags`, v1 and v2 layouts) into mode, MCS, streams,
width and guard interval, and computes the PHY rate from first principles
(`ieee80211_haiku_mcs_kbps()` in the OpenBSD compat `ieee80211_node.h`:
data subcarriers x bits x coding rate x streams / symbol time, for HT, VHT
and HE). The private `IEEE80211_IOC_HAIKU_TX_RATE` ioctl returns it; other
OpenBSD drivers fall back to the legacy rate net80211 keeps. The value is the
rate the firmware last selected, so it changes only when rate control sends an
update. Verified on the board: "58.5 Mbps (HE MCS 3, 2 streams, 20 MHz)",
matching the 802.11ax table for 3.2 us GI. The applets also no longer paint a
background, so Deskbar's own tray shows through.

**Bluetooth applet** (`src/apps/bluetoothstatus`, replaces the server's
replicant when installed): the Bluetooth rune, faded while the service is not
running, with a green status light while a device is connected. The menu lists
paired LE and Classic devices with type icons, connected state and a battery
gauge; Alt-click adds address, type and battery. Battery comes from the input
add-on, which reads Battery Level (0x2A19), subscribes to its notifications
(or polls every 10 minutes) and publishes connection state and level through
`LEDeviceStatus` (`~/config/settings/bluetooth/le_status`, ignored after a
reboot). **Classic devices have no battery or live connection state yet**
(that needs HFP/AVRCP battery reporting and a server query for link state).
The applet compiles the two kit files it needs in, because Deskbar may resolve
an older system `libbluetooth.so`.
